# 📸 Grid IP Scanner2 - 딥 스냅샷 비교 엔진 및 스튜디오 기술 명세서
## (Deep Snapshot Comparison Engine & Diff Studio Specification v2)

본 문서는 **Grid IP Scanner2 (v2.4.5)**에 새롭게 탑재된 **차세대 딥 스냅샷 비교 엔진(Deep Diff Engine v2)**과 **1:1 Side-by-Side 스냅샷 비교 스튜디오(Snapshot Diff Studio)**의 아키텍처, 상태 판별 알고리즘, 보안 위협 감지 로직 및 사용자 인터페이스 사양을 규정합니다.

## 📌 1. 기존 스냅샷 비교 방식의 한계와 전면 개편 배경

### 1.1. 기존 방식의 문제점
1. **1차원적 종속 비교**:
   - 오직 `현재 실시간 스캔 결과(results)`와 `1개의 선택된 과거 스냅샷`만을 대조할 수 있어, **"어제 스냅샷 A vs 오늘 스냅샷 B"**, **"정기 점검 전 vs 점검 후"**와 같이 과거 시점 간의 교차 비교가 원천적으로 불가능했습니다.
2. **256 그리드 셀 클릭 의존성**:
   - 16x16 그리드 상에서 셀 색상만 변경될 뿐, 어떤 장치가 어떻게 변경되었는지 목록 형태로 파악할 수 없어 256개 셀을 일일이 클릭해야만 하는 비효율이 존재했습니다.
3. **핵심 보안 지표(포트/MAC/지연시간) 누락**:
   - 단순 활성/비활성 판별 위주로 구현되어, 새로 열린 보안 취약 포트(3389 RDP, 445 SMB, 23 Telnet 등), IP 충돌(동일 IP에 다른 MAC 할당), RTT 레이턴시 급변을 체계적으로 분석하지 못했습니다.

### 1.2. 신규 딥 비교 엔진(Deep Diff v2)의 핵심 목표
* **완전한 다자간 교차 대조**: 실시간 스캔뿐만 아니라 보관된 임의의 스냅샷 2개 간(A ↔ B)의 완전 자유 교차 비교.
* **1:1 Side-by-Side 테이블**: [기준점 A]와 [비교점 B]의 상태, MAC, 제조사, 호스트명, 개방 포트, RTT를 나란히 대조.
* **보안 위협 심층 분석**: MAC 변경(IP 충돌/스푸핑 의심), 취약 포트 신규 노출을 자동 탐지하여 경보 발생.
* **실무 보고서 연동**: 엑셀 CSV 원클릭 내보내기 및 IT 관리자 보고용 텍스트 요약 복사 지원.

## 🔍 2. 딥 비교 판별 알고리즘 (`services/diffEngine.ts`)

엔진은 두 시점의 스캔 데이터셋($S_A, S_B$)에 존재하는 모든 IP 집합($U = IP(S_A) \cup IP(S_B)$)을 전수 순회하며 아래 조건에 따라 상태를 정밀 분류합니다:

```text
       ┌───────────────┬──────────────────────────────────────────────┐
       │   조건        │                    상태 및 진단 분류          │
       ├───────────────┼──────────────────────────────────────────────┤
       │ Active(B) &   │ + NEW (신규 접속)                            │
       │ !Active(A)    │ - 신규 감지 노드 (MAC, 호스트, 개방포트 기록)  │
       ├───────────────┼──────────────────────────────────────────────┤
       │ !Active(B) &  │ - OFF (오프라인 이탈)                        │
       │ Active(A)     │ - 장비 전원 차단 / LAN 케이블 분리           │
       ├───────────────┼──────────────────────────────────────────────┤
       │ Active(B) &   │ ! CHG (속성/보안 변동) 또는 = SAME (동일 유지)│
       │ Active(A)     │  1) MAC 변경: ⚠️ IP 충돌 / ARP 스푸핑 의심   │
       │               │  2) 포트 변경: +신규 개방 / -차단 포트       │
       │               │  3) 호스트명/제조사 변경: 자산 식별자 변동    │
       │               │  4) RTT 편차: 40ms 이상 지연/개선            │
       └───────────────┴──────────────────────────────────────────────┘
```

### 2.1. 보안 위험 포트 자동 감지 (High-Risk Vector)
비교 대상에서 아래 11개 주요 관리/원격/데이터베이스 포트가 신규 개방(`+`)될 경우 `hasSecurityRisk = true` 플래그 및 `securityAlertCount`를 즉각 상향합니다:
* **원격 접속/관리**: `21` (FTP), `22` (SSH), `23` (Telnet), `3389` (RDP), `5900` (VNC)
* **네트워크 공유/인프라**: `80` (HTTP), `445` (SMB/랜섬웨어 전파 경로), `8080` (Web Proxy)
* **데이터베이스**: `1433` (MS-SQL), `3306` (MySQL), `6379` (Redis)

### 2.2. MAC 주소 불일치 감지 (IP Conflict & ARP Spoofing Guard)
동일한 IP 주소에 대해 기준점과 비교 시점의 MAC 주소가 서로 다를 경우:
$$\text{MAC}_A \neq \text{MAC}_B \implies \text{CRITICAL ALERT}$$
IP 주소 충돌, 허가받지 않은 사설 장비의 IP 탈취, 또는 ARP 스푸핑 공격 가능성을 명시적으로 경고합니다.

### 2.3. 변동(!CHG) 오탐 방지 및 별칭(Alias) 독립성 보장 (False-Positive Guard)
1. **사용자 정의 별칭(Alias)의 완전한 독립성**:
   - 기기 별칭(Nickname) 및 관리자 메모는 로컬 브라우저 UI 표시 전용 메타데이터이며, 네트워크 물리 스캔 스냅샷의 핵심 데이터 모델(`ScanResult`)과 물리적으로 분리되어 있습니다.
   - 따라서 **별칭을 추가, 수정, 삭제하더라도 스냅샷 비교 변동(!CHG) 판정에는 0%의 영향도 미치지 않습니다.**
2. **핑 지연시간 편차 디커플링 (Latency Decoupling)**:
   - Wi-Fi 또는 일시적인 트래픽 지연으로 인한 핑 편차(예: 2ms ➔ 55ms)만으로는 절대 `!CHG` 상태로 승격되지 않습니다.
   - 변동(!CHG)은 오직 **MAC 주소 변동, 호스트명 변경, 제조사 변경, 개방 포트 추가/삭제** 등 실제 물리적·논리적 장비 정보가 바뀌었을 때만 트리거됩니다.
3. **MAC 및 호스트명 정규화 (Normalization)**:
   - MAC 주소의 하이픈/콜론 구분자 및 영문 대소문자 차이를 통일하여 포맷 불일치로 인한 오탐을 원천 차단합니다.
   - mDNS `.local` 접미사 및 임시 플레이스홀더('Unknown Device', 'Hidden Node', '-')는 정규화 필터를 거쳐 동일 장비로 정확하게 인식합니다.

### 2.4. 미할당 빈 IP 슬롯 격리 및 고대비 시각 차별화 (v2.4.6)
1. **미할당 비활성 IP 슬롯 격리 (`!Active(A) && !Active(B)`)**:
   - 기준점과 현재 시점 모두 비활성인 240여 개의 빈 IP 슬롯은 `diffMap` 등록 및 `sameCount`에서 완전히 제외됩니다.
   - `sameCount`는 오직 **과거 스냅샷 기준점에 등록되어 있고 현재도 온라인으로 정상 유지 중인 실제 장비 수**만 정확히 반영합니다.
2. **신규 탐지 장비(+NEW) vs 스냅샷 기준 장비(=BASE) 시각 계층**:
   - **신규 노드 (+NEW)**: 생동감 있는 에메랄드 그린 발광, 애니메이션 펄스 핑 닷(`animate-ping`), `ring-2 ring-emerald-400`, `+ 신규` 배지로 최우선 부각.
   - **기준 장비 (=BASE)**: 선택한 4개 기준 테마(하늘, 보라, 청록, 회색)의 견고한 메탈릭 배경과 2중 링 테두리, `= 기준` 배지로 안정적으로 식별.
   - **빈 IP 슬롯**: 배지와 링 없이 다크 그리드 배경으로 디밍(`opacity-20`) 처리되어 실제 장비들의 시각적 인지성을 극대화.

## 🎯 4. 사용 방법 및 권장 워크플로우

1. **정기 점검 / 변경 전**:
   - 메인 화면 상단 Diff 툴바에서 `새 스냅샷 저장`을 눌러 기준선(예: "정기점검 전 2026-10-21")을 캡처합니다.
2. **장비 교체 / 방화벽 정책 변경 후**:
   - 새로운 스캔을 완료한 후, `스냅샷 1:1 대조 스튜디오 (Studio)` 버튼을 클릭합니다.
3. **1:1 대조 및 이상 징후 분석**:
   - 상단에서 [A: 점검 전 스냅샷]과 [B: 현재 실시간 스캔]을 선택합니다.
   - `보안 경보` 탭을 눌러 새로 노출된 취약 포트나 MAC 변경 장비가 있는지 점검합니다.
   - `오프라인` 탭을 눌러 점검 후 정상 복구되지 않은 필수 서버/단말기를 확인합니다.
4. **결과 보고**:
   - `CSV 내보내기` 또는 `요약 복사`를 눌러 팀 공유 및 이력 관리를 완료합니다.

## 📐 5. 상단 툴바 레이아웃 최적화 및 잘림 방지 아키텍처 (v2.4.6)

### 5.1. 상단 내용 잘림 원인 및 해결 (Zero-Clipping Architecture)
- **기존 원인**:
  - Diff 진단 패널이 메인 그리드와 동일한 스크롤 컨테이너(`overflow-y-auto`) 내부에 종속 배치되어 있어, 그리드 렌더링 시 스크롤 포커스가 아래로 이동하거나 화면 높이가 낮은 디바이스에서 최상단 툴바 및 컨트롤 버튼들이 상단 헤더 뒤로 밀려 잘리는 현상 발생.
  - 하단에 불필요한 장문의 가이드 안내 박스가 추가 공간을 차지하여 전체 뷰포트 높이를 초과 유발.
- **개선 아키텍처**:
  1. **독립된 서브헤더 고정 배치 (Sub-Header Pinning)**: Diff 제어 툴바를 스크롤 가능한 본문 내부가 아닌, 메인 `<header>` 직하단의 독립적인 서브헤더 레이어로 승격 (`z-20 shrink-0 border-b`).
  2. **하단 설명 박스 전면 제거**: 하단의 불필요한 설명 텍스트 박스를 영구 삭제하여 뷰포트 점유율 45% 절감.
  3. **초고밀도 2행 설계 (2-Row Compact Grid)**:
     - 1행: Diff 상태 배지, 기준점 드롭다운, 스냅샷 캡처 버튼, 1:1 대조 스튜디오 버튼, 가이드/복귀 버튼.
     - 2행: 실시간 4종 카운터 버튼(+NEW, -OFF, !CHG, =SAME), 색상 범례 및 원클릭 기준 색상 스위처.
  4. **그리드 높이 동적 계산**: `calc(100vh - 190px)` 적용으로 16x16 그리드와 서브헤더 툴바가 스크롤 없이 단일 화면에 100% 온전히 표시됨.

## ⏰ 6. 정기 자동 네트워크 스캔 스케줄러와의 상호 연동 (Integration with Scheduled Scan)

### 6.1. 자동 스냅샷 아카이빙 (`[Auto-Sched]`)
- 정기 자동 스캔 스케줄러(`services/schedulerService.ts`, `components/ScheduleModal.tsx`)가 활성화된 주기(예: 매 30분, 매 1시간)마다 스캔을 완료하면, 사용자의 수동 조작 없이도 즉시 고유 타임스탬프가 각인된 `[Auto-Sched] 스케줄명 (HH:MM)` 스냅샷이 자동 생성됩니다.
- 스냅샷 저장소는 최대 25개까지 시계열 순서로 자동 순환 보존되며, 네트워크 관리자는 별도의 수동 백업 없이도 하루 종일 발생한 모든 장비 접속/이탈 이력을 완벽히 보존할 수 있습니다.

### 6.2. 1:1 Side-by-Side 스튜디오 즉시 연동
- 스케줄러 [자동 실행 기록] 탭에서 특정 실행 이력의 `[📸 스냅샷 Diff 보기]` 버튼을 클릭하면, 해당 자동 생성 스냅샷이 즉시 1:1 대조 스튜디오의 비교 소스로 로드되어 어떤 장비가 신규 추가(+NEW)되었거나 무단 이탈(-OFF)했는지 단 1초 만에 시각적으로 대조할 수 있습니다.
